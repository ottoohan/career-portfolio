# AI 에이전트 업무 환경 이식 가이드

> 회사를 옮겨도 그대로 가져가는 것은 쌓인 지식이 아니라 **지식이 쌓이는 구조**다.
> 이 문서는 재직 마지막 해에 Claude Code로 QA·개발·기획·데이터 업무를 하며 정착한 구조를 새 회사에서 다시 세우는 순서를 적은 것이다.

---

## 0. 경계선 — 가져가는 것과 두고 가는 것

| | 가져간다 (내가 만든 방법) | 두고 간다 (회사 정보) |
|---|---|---|
| 규칙서(CLAUDE.md) | 섹션 구성, 규칙 문장 패턴, 완료 정의 표 | 레포명·티켓 접두어·도메인·데이터소스 번호·계정 |
| 메모리 | 폴더 구조·파일 서식·분류 체계·운영 규칙 | 파일 내용 전부 |
| 스킬·에이전트 | 절차 설계, 출력 형식 | 사내 문서 표준·업로드 경로·URL |
| 훅·스크립트 | 판정 로직(이 폴더 `templates/`에 회사 정보 없이 다시 작성) | 회사 레포에 커밋된 원본 |
| 자격증명 | `~/.<회사>/*.json` + 권한 0600 패턴 | 키 자체 (퇴사 시 파기) |

옛 회사의 사실은 새 회사에서 **틀린 사실**이다. 남겨 두면 판단을 망친다. 메모리는 빈 상태로 시작한다.

## 1. 구조 한눈에 보기

```
~/<회사>-source/                       작업 루트. 그 아래에 회사 레포들을 클론
├── CLAUDE.md                          개인 규칙서 (gitignore, 매 세션 자동 로드)
├── .claude/
│   ├── settings.json                  권한 allow/deny, 훅 등록
│   ├── hooks/push_guard.py            되돌릴 수 없는 것만 기계 차단
│   ├── agents/independent-verifier.md 구현자 설명 없이 반박형으로 검증
│   └── skills/<이름>/SKILL.md          3번 이상 반복한 일만
├── bin/<조회 래퍼>                     키 비노출·쓰기 차단·최신성 검사
└── artifacts/<티켓>/                   스크린샷·SQL·분석 결과, PROGRESS.md (gitignore)

~/.claude/projects/<루트 경로 슬러그>/memory/
├── MEMORY.md                          한 줄 인덱스 (매 세션 자동 로드)
└── <주제>.md                           사실 하나당 파일 하나
```

| 층 | 역할 | 틀리면 어떻게 드러나나 |
|---|---|---|
| CLAUDE.md | 모든 작업에 걸리는 규칙 | 매번 읽히니 바로 드러남 |
| 메모리 | 사람·프로젝트·함정·외부 자료 | 다음 세션에서 틀린 판단으로 드러남 → 즉시 삭제 |
| 스킬·에이전트 | 반복 절차의 고정 | 안 쓰이면 분기마다 폐기 |
| 훅 | 복구 불가 동작 차단 | **조용히 죽는다** → 등록 시 실행 검증 필수 |
| 래퍼 스크립트 | 위험한 외부 호출을 한 곳에 | 출력에 실행 시각·최신성 표기 |

## 2. 규칙서(CLAUDE.md)에 꼭 넣는 규칙 10개

전체 뼈대는 [`templates/CLAUDE.md.template`](templates/CLAUDE.md.template). 그중 실제로 효과가 컸던 규칙들:

| # | 규칙 | 왜 (실측 근거) |
|---|---|---|
| 1 | **기준 먼저 출력**: 조회·산출 전 첫 줄에 `기간 / 모수 / 집계 단위 / 환경 / 형식` 가정을 적고 바로 진행 | 한 달 교정 41건 대부분이 "누적 말고 월별", "메인 말고 베스트" 같은 기준 오해였다. 묻지 않고 보여 주면 틀린 줄에서 바로 잡힌다 |
| 2 | **선택지 질문 금지, 권장안 선실행** + 첫 줄에 `선택: X (이유) / 대안: Y`. 되돌릴 수 없는 작업만 먼저 묻는다 | 질문 왕복이 결과물보다 비싸다 |
| 3 | **완료 정의(DoD) 표**: 작업 종류별로 "완료"라고 말할 조건 | "됐습니다"만 있는 보고를 없앤다. 코드 수정 = 테스트 출력 + 독립 검증 + 배포 환경 URL |
| 4 | **실측과 추정을 구분 표기** | 추정을 사실처럼 쓴 QA 티켓 하나는 개발자가 조사한 뒤 철회됐다 |
| 5 | **절대 금지 목록** (운영 DB 쓰기, 강제 push, 실고객 발송, 자격증명 출력) | 훅이 막지 못하는 것까지 문장으로 박아 둔다 |
| 6 | **환경 ↔ 브랜치 매핑 표** | "QA1에 올려줘"를 레포마다 다른 브랜치 이름으로 바꾸는 일을 매번 틀렸다 |
| 7 | **반복 업무 → 스킬 이름 표** | 프롬프트로 같은 설명을 다시 하지 않는다 |
| 8 | **한 세션 = 한 티켓 + PROGRESS.md** | 수천 분짜리 세션은 압축 뒤 맥락이 섞여 누락이 생긴다 |
| 9 | **산출물은 `artifacts/<티켓>/`** | 루트가 스크린샷으로 덮이지 않고, 나중에 근거를 찾을 수 있다 |
| 10 | **매번 틀리는 것들** 섹션 | 가장 값어치 있는 부분. 메모리 3곳 이상에 나온 함정은 여기로 승격 |

## 3. 메모리 운영 규칙

서식은 [`templates/memory/`](templates/memory/).

- **타입 4종**: `user`(나는 누구) · `feedback`(일하는 방식 지시, 왜 포함) · `project`(진행 중인 일, 현재 상태 포함) · `reference`(외부 자료·환경 함정)
- **적을 것은 "코드를 읽어도 모르는 것"**: 왜 그렇게 됐나, 어디서 사고가 났나, 무엇을 건드리면 안 되나. 코드 구조·git 이력은 적지 않는다.
- **진행 중 항목에는 현재 상태를 쓴다** ("대기: 리뷰 → QA 머지"). 상태가 없는 항목은 완료 로그로 옮긴다.
- **상태는 실측해서 갱신한다**: 정리할 때 PR·배포 이력을 조회해 보니 "대기: main 머지" 11건이 이미 머지돼 있었다.
- **인덱스가 150줄을 넘으면 완료 항목을 로그 파일로 옮긴다.**
- **같은 함정이 3곳 이상 나오면 규칙서로 승격**하고, 사례가 2건 이상 모이면 버그 패턴 DB에 교차 패턴으로 묶는다.
- **로컬 메모리로 결론 내리지 않는다**: 메모리는 내가 기록한 것만 있다. 경력 정리 때 로컬만 보고 "기획 증거 부족"이라 판단했다가 위키를 열자 전부 뒤집혔다.

## 4. 검증 구조 — AI가 "됐다"고 하는 걸 믿지 않는 장치

| 장치 | 내용 | 템플릿 |
|---|---|---|
| 독립 검증 에이전트 | 구현자의 결론·테스트 결과를 **넘기지 않고** diff와 기대 결과 문장만 준다. 경계값·상태 전이·목록/건수 불일치·계약 불일치·권한·캐시·회귀 관점으로 반례를 찾는다 | [`agents/independent-verifier.md`](templates/agents/independent-verifier.md) |
| 읽기 전용 조회 래퍼 | 키를 파일에서 읽고 출력하지 않는다. 쓰기문은 거부하고, 잡은 2초 간격 최대 30회 폴링한다. 결과에 실행 시각(현지 시간)을 붙인다. "0건" 판정 쿼리에는 활성 테이블의 최근 기록 시각을 같이 본다 | 2절 규칙 + 아래 체크리스트 |
| 최신성 검사 | "실시간" 복제 DB도 멈춘다. 최근 기록 시각과 현재 시각 차이가 몇 분 이상이면 판정하지 않고 "미확인" | — |
| 배포 후 실측 | 머지 ≠ 배포 ≠ 반영. 대상 환경 도메인에서 번들·화면·API 응답으로 확인한 URL을 결과에 남긴다 | DoD 표 |

**조회 래퍼 체크리스트** (회사 BI 도구 API에 맞춰 새로 만든다)
- [ ] 키는 `~/.<회사>/<서비스>-credentials.json`(0600)에서 스크립트 안에서만 읽는다
- [ ] `INSERT|UPDATE|DELETE|DROP|ALTER|TRUNCATE`로 시작하는 문장은 거부한다
- [ ] 응답을 상태 코드로만 판정하지 않는다 (없는 경로가 200 + HTML을 주기도 한다)
- [ ] 출력 첫 줄에 데이터소스, 실행 시각, 행 수를 붙인다
- [ ] `--fresh <테이블.시각열>` 옵션: 최근 기록과 현재 시각의 차이를 출력한다
- [ ] 자격증명 폴더는 `ls·cat·head` 탐색을 settings.json deny로 막는다

## 5. 훅은 얇게

- 훅은 **"기계적으로 판정 가능 + 어기면 되돌릴 수 없음"** 두 조건을 모두 만족할 때만 쓴다. 예: 강제 push, 보호 브랜치 push, 키 유출.
- 실제로 겪은 일: 커밋 품질 훅이 셸 따옴표 오류로 **6개월 동안 아무 동작도 안 했다**. `2>/dev/null`이 에러를 삼켜서 아무도 몰랐다. 게다가 고쳐 살렸다면 한국어 커밋을 막아 규칙서와 충돌할 뻔했다.
- 그래서: 등록하면 **실제 JSON 입력을 파이프로 넣어 검증**하고, 에러를 삼키지 않는다.
- [`templates/hooks/push_guard.py`](templates/hooks/push_guard.py)는 [`test_push_guard.py`](templates/hooks/test_push_guard.py)의 28개 입력으로 검증한다. 일반 push, `HEAD:main`, `-f`·`-fu` 묶음, `--force-with-lease`, `+refspec`, `--all`·`--mirror`·`--delete`, `git -C`·`-c`·`--no-pager` 전역 옵션, `&&` 연결, `bash -c` 중첩, 문자열 안의 명령, 인자 없는 push와 `HEAD`의 현재 브랜치 판정이 들어 있다. 판정이 애매하면 막는다(fail-closed).
- 새 우회 방법을 발견하면 테스트 입력부터 추가하고 훅을 고친다.
- "단계 강제", "세션 쪼개기"처럼 모델의 판단을 대체하려는 장치는 만들지 않는다. 플랜 모드·워크트리처럼 플랫폼이 이미 흡수한 기능이 많다.

## 6. 개선은 로그 실측으로

감으로 셋업을 고치지 않는다. 한 달에 한 번 [`templates/scripts/session_metrics.py`](templates/scripts/session_metrics.py)로 기준선을 잰다.

| 지표 | 뜻 | 바꿀 것 |
|---|---|---|
| 교정률 | 두 번째 이후 발화의 앞 80자에 "아니, 말고, 다시 해" 같은 표현이 있는 비율(키워드 방식이라 오탐 있음) | 교정 문구를 직접 읽어 분류하고 규칙서에 한 줄 추가 |
| 권한 거부 | 사용자가 거부한 도구 실행 | 반복되는 거부는 deny 규칙이나 래퍼로 |
| 세션당 스킬 호출 | 스킬·슬래시 명령 호출 수 ÷ 세션 수 | 가장 많이 하는 일에 스킬이 없으면 만든다 |
| 장시간 세션 | 300분 초과 | 1세션 1티켓 규칙 점검 |
| 도구 상위 10 | 반복 호출 | 즉석 스크립트 400회 → 래퍼 하나로 |

실제 적용 결과와 1주 중간 측정은 [3-why-me](../3-why-me/README.md#4-측정으로-개선한다)에 있다.

## 7. 새 회사 셋업 순서

### 1일차 (30분)
```bash
mkdir -p ~/<회사>-source && cd ~/<회사>-source   # 레포들을 이 아래로 클론
claude
> /init                                          # 코드베이스 기반 CLAUDE.md 초안
```
초안에 [`CLAUDE.md.template`](templates/CLAUDE.md.template)의 섹션을 덧붙이고 회사 값으로 채운다. 먼저 채울 것은 사용자 컨텍스트, 레포 표, 절대 금지, 완료 정의다.

### 1주차
| 할 일 | 방법 |
|---|---|
| 훅 1개 | `push_guard.py`·`test_push_guard.py` 복사 → 보호 브랜치 이름 수정 → 테스트 실행 |
| 권한 정리 | 반복 승인되는 읽기 명령을 allow로, 자격증명 탐색은 deny로 |
| 도구 연결 | 이슈 트래커 → 위키 → 메신저 순서로 MCP 연결 |
| 환경 표 | 레포별 환경 ↔ 브랜치 ↔ 도메인 매핑을 배포 워크플로 파일에서 확인해 표로 |
| 첫 메모리 | 로컬 실행 함정(런타임 버전·빌드 조건), 테스트 계정, 헷갈리는 메뉴 경로 |

### 1개월차
- 3번 이상 반복한 일 3개를 골라 스킬로 만든다. 예: 문의 원인 판정, 테스트케이스 작성, 지표 집계.
- 독립 검증 에이전트를 붙이고 완료 정의 표에 넣는다.
- 조회 래퍼를 만든다.
- `session_metrics.py`로 첫 기준선을 잰다.

### 분기마다
- 안 쓰이는 스킬은 폐기한다. 틀린 메모리는 삭제한다(오래된 사실은 없느니만 못하다). 훅은 파이프 테스트로 다시 확인한다.

## 8. 자주 하는 실수

| 실수 | 대신 |
|---|---|
| 스킬을 일찍 만든다 | 세 번 반복해서 패턴이 보인 뒤에 만든다 |
| 자격증명을 명령어에 직접 쓴다 | 대화 기록·셸 히스토리에 영구히 남는다. 처음부터 파일에서 읽는다 |
| 위키·검색 API 결과를 전부라고 믿는다 | 검색은 조용히 잘린다(예: 60건 상한). 기간을 잘라 여러 번 조회한다 |
| "0건"을 바로 결론으로 쓴다 | 데이터 최신성부터 확인한다 |
| 병렬 작업에 stash를 쓴다 | 워크트리끼리 stash를 공유해 작업이 뒤섞인다. 레포별로 `git worktree add`를 쓴다 |
| 규칙을 메모리에만 둔다 | 모든 작업에 걸리는 규칙은 규칙서로 옮긴다 |
