# 한지만 — QA + 운영지원(Product Operations)

> QA 5년. 결함을 막는 QA에, 운영자가 쓰는 도구를 고치고 운영 문의를 판정해 닫는 운영지원을 더했습니다.
> 원인은 코드에서 찾고, 고칠 수 있는 건 직접 고치고, 결과는 다시 잽니다. 내가 만든 숫자도 다시 재서 틀리면 고칩니다.

| 오픈 전에 막은 것 | 운영 문의를 닫는 일 | 내 계산도 다시 잰다 | 결제 QA |
|---|---|---|---|
| 프로모션 29종의 가격 설계를 오픈 전날 교차 검증 → **수정 요청 8건**, 그중 행사 종료 뒤 2년간 할인가로 팔릴 뻔한 종료일 오타 포함 → [사례 13](2-career-flow/cases/13-promotion-price-crosscheck.md) | 판정 틀(결함 / 운영 실수·오해 / 정책)로 오늘 할 조치와 근본 수정 티켓을 한 답글로, 안내·시연·대응 **345건+** 직접 공유 → [사례 12](2-career-flow/cases/12-ops-inquiry-triage.md) | 크리티컬 유출률 첫 보고 3.40%의 **분모 결함을 직접 찾아 정정** → 실제 1.09%·1.52%(반기 차이는 표본 7·9건이라 판별 불가) → [사례 02](2-career-flow/cases/02-measuring-escape-rate.md) | 전수 TC **290건**, 자동화 36건 중 실패 2건 모두 실결함 |

운영 지표(채널 전체, 인과 주장 안 함): 운영 실수가 원인인 요청 비율 13.9% → 9.7% · 첫 실질 답변 중앙값 14분 → 9분 · 개발자 데이터 보정으로 끝난 문의 13% → 5% → [경력기술서 0절](2-career-flow/경력기술서.md#0-운영지원--운영-문의를-판정하고-닫기)
