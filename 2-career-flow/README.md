기준을 2025.12 한 달로 잡은 것은 이 정의로 처음 잰 달이 12월이라서다. 2026년 1~4월은 재지 않았다.

응답 시간은 Slack 기록 시각으로 잰 값이다("확인해 볼게요"·이모지 같은 접수 표시는 빼고 첫 실질 답변 기준, 근무시간 보정 없음). 종결 유형은 AI가 스레드 결론을 읽고 판정했다.

**무엇을 했나**
- **실수가 나던 자리에 가드를 넣었다**(프론트 단독은 직접 구현, 서버 변경은 개발자와 함께) — 필수 강의 수강률 0% 저장 차단, 설문 설명 글자 수 초과를 저장 전에 안내, 과제 양식 변경 시 기존 과제가 지워지던 경로 차단, 팝업 노출 시각 표기 오류 수정 등. 만족도 조사 의견에서 출발해 코드에서 원인을 확인한 것들이다([사례 01](cases/01-backoffice-as-product.md)).
- **사용법을 모르는 사람에게 먼저 알렸다** — 운영 부서 채널에 직접 올린 운영지원 메시지 **345건 이상**(2025.01~2026.11, 키워드 검색 기준 최소치).

  | 유형 | 건수 | 예 |
  |---|---|---|
  | 정책·사용법 안내 | 66 | 문자 발송이 자동으로 걸러지는 조건, 수강후기가 언제·어떤 설정에서 노출되는지, 이미 있는 기능의 사용법 |
  | 새 기능 배포 안내·시연 | 95 | 잔여수량 표시 설정 어드민화(시범 운영 + Q&A 세션), 동영상 일괄 등록(대면 가이드), 조편성 엑셀 업로드 |
  | 운영 문제 대응 | 184 | 외부 영상 서버 장애 시 고객 응대 가이드, 탈퇴가 막히는 문제의 원인과 우회 방법 |

  2025년에는 문제 대응이 대부분이었고, 2026 상반기부터 배포 안내가 문제 대응을 앞섰다. 공지는 "배경 → 바뀐 점 → 사용 방법 → 유의사항" 순서로 고정했다.
- **문의마다 원인을 판정했다** — 시스템 결함인지 운영 실수인지, 운영 조치로 끝낼지 개발이 필요한지까지 정리하고, 판정 형식을 도구로 고정했다.

**읽을 때 주의**
- 운영 실수 비율은 같은 정의(운영자의 설정·조작 실수 또는 동작 오해가 주원인. 가드가 없어 실수가 통과한 건 포함, 고객 오사용·개발 실수·원인 미확인 제외)로 **AI가 스레드 결론을 읽고 분류한 값**이다. 월별로 나눠 분류한 뒤 같은 정의로 한 번 더 일괄 재판정했고(1차 대비 −11 / +1건), 사람이 전수 검수하지는 않았다. 경계 사례를 넣고 빼면 10월 기준 8.1~12.9%로 움직인다.
- 월 2~15건 규모라 1건에 1~2%p씩 흔들린다. 9월에는 15.5%로 기준선보다 높았다. 가드를 배포한 달 다음에 비율이 내려간 경우(6월 → 7월)도, 그렇지 않은 경우도 있어서 가드와 비율의 인과는 주장하지 않는다.
- 요청 건수 감소를 어드민 개선 하나의 효과로 주장하지 않는다. 같은 기간 조직·상품 구성도 바뀌었다. 내가 말할 수 있는 것은 "운영 실수 비율을 같은 정의로 재기 시작했고, 그 기간에 비율과 요청이 함께 줄었다"까지다.

## 2. FE 개발 — 원인을 찾은 사람이 직접 고친다

**사용자 웹 (Next.js / React, 커밋 110건)**
- 페이지 이동 직전 분석 이벤트 유실: 1차 수정 후 재발을 잡고 SDK 직렬 전송 구조까지 내려가 재현, 2차 수정 기준 제시(반영 대기) → [사례 03](cases/03-event-loss-before-navigation.md)
- 예외 없이 null을 돌려주는 코드가 폴백 체인을 끊어 안내 팝업이 안 뜨던 문제 수정
- 백엔드가 내려주는 "공개 예약" 필드를 프론트가 소비하지 않아 예약 교재가 노출되고 400이 나던 문제 수정
- 대기 신청 상태의 공유 버튼 누락, 상담 입구 A/B 노출, 광고 플랫폼 전용 구매 이벤트, iOS 다운로드 파일명 핫픽스

**운영 백오피스 (Vue 3 / Nuxt 3, 커밋 161건)**
- 만족도 조사 의견을 코드에서 원인 확인 → 범위 A(프론트 단독)는 직접 구현 → [사례 01](cases/01-backoffice-as-product.md)
- 세션 갱신 대기열이 폐기되며 요청이 증발하던 "무반응" 결함, 모달 드롭다운이 마스크 뒤에 깔리던 z-index 결함
- 할인율 입력 칸이 판매가를 변조하던 결함, 수강기간 일괄 변경의 2,000건 잘림 진단 → [사례 05](cases/05-silent-2000-cap.md)
- 팝업 복제(오랫동안 빈 함수), 날짜 포맷 분·월 뒤바뀜, 조 편성 엑셀에 조장 선발용 이력 열 추가

## 3. BE 개발 — 목록·건수·엑셀이 같은 조건을 보게

## 5. 데이터 분석·성과 측정 — 감으로 내려지던 결정을 숫자로

| 질문 | 분석 | 바뀐 결정 |
|---|---|---|
| 시즌 프로모션의 결제를 누가 이끌었나 | 결제 기여 비중: 홈 배너 14.7% vs 실시간 방송 플로팅 창 2.16% (**약 7배**) | 다음 시즌 배치 우선순위 변경 (가설 반증) |
| 오픈 알림 신청자가 왜 결제까지 안 오나 | 퍼널 이탈의 병목은 발송 부족이 아니라 **알림 클릭률** | 발송 증량안이 효과 없음을 입증 |
| QA 지원 요청이 왜 밀리나 | 4주 인입 분류: 요청이 특정 인원에 집중, **즉시 대응이 필요한 건은 약 3분의 1** | 나머지는 배치 처리로 전환 가능하다는 결론 |
| 검색 유입이 왜 크게 줄었나 | 유입 경로별 분해(유료는 오히려 증가, 검색만 급감) → 검색 콘솔의 색인·노출·크롤 지표 → 봇 UA 크롤 표본 30건 → 검색엔진 공식 업데이트 일정 대조 | 색인은 정상인데 노출만 사라졌고, 절벽 날짜가 코어 업데이트 시작일과 일치 → **기술 원인을 닫고** 콘텐츠 품질 대응으로 범위 한정 |
| 운영 실수는 줄고 있나 | 지원 요청을 4개 유형으로 태깅, 휴먼에러 비율을 같은 정의로 매주 자동 집계 | 구성원 목표 두 개가 같은 원천 데이터를 쓰게 함 |
| 백오피스 개선이 체감되나 | 월간 고정 문항 만족도 | 8.23 → **9.33** (월간 6회, 최종 15명 응답), 개선 PR +96% |
