# AI 답변을 재 보니 문제는 찾기였다 — RAG 평가 실험

**역할**: 사내 RAG 연구 스터디 4부 "RAG 평가" 발표자 · 실험 설계 · 사람 판정 · AI 채점자 보정
**기간**: 2026.10 ~ 11
**상태**: 실험·발표 완료(11/11). AI 채점자 일치율은 새 표본으로 다시 재기 전까지 "검증 중"
**한 줄**: 사내 위키로 질문 40개짜리 시험지를 만들고 검색 방식을 바꿔 가며 세 번씩 돌렸다. 정답 문서를 주면 36개를 맞혔지만 검색을 거치면 22~25개였다. 고칠 곳은 답을 만드는 모델이 아니라 찾는 쪽이었다.

---

## 문제
- 개발본부가 AI 개발 프레임워크 다음 과제로 RAG(문서를 찾아 답하는 AI)를 연구하기로 했다. 그런데 "답이 좋아졌다"를 판단할 기준이 없었다.
- AI 답변은 같은 질문에도 매번 조금씩 다르다. 한 번 돌려 보고 좋다/나쁘다를 말하면 우연을 성과로 착각한다.
- 채점을 AI에게 맡기면 빠르지만, 그 채점자가 사람과 같은 판단을 하는지는 아무도 재지 않았다.

## 접근
| 설계 | 내용 |
|---|---|
| 코퍼스 | 사내 위키 문서 수백 개 |
| 시험지(골든셋) | 40문항 — 사실 20 · 여러 문서 종합 8 · 답 없음 8 · 혼동 유도 4. 정답은 "이 중 하나 / 이것 모두" 그룹으로 |
| 비교 조건 | 단어 단위 BM25 · 바이그램 BM25 · 정답 문서를 직접 준 경우(오라클) |
| 분리 | 답을 만드는 모델과 채점하는 모델을 다르게 |
| 반복 | 조건마다 3회 실행, 문항별 다수결 |
| 실사용 확인 | 지원 채널에 실제로 들어온 질문 160여 개 |
| 채점자 보정 | 사람이 직접 판정한 25건과 AI 채점 결과를 맞춰 보고 채점 기준을 다듬음 |

## 결과
| 발견 | 값 | 그래서 |
|---|---|---|
| 합격 문항 (3회 다수결) | 단어 22/40 · 바이그램 25/40 · **정답 문서 제공 36/40** | 병목은 찾기. 검색 방식끼리는 차이가 유의하지 않고(p=0.51), 검색과 정답 제공의 차이는 유의(정확 McNemar, p=0.001) |
| 판정 흔들림 | 5~10% 문항이 3회 중 판정이 갈림 | 한 번 실행으로 판정하지 않는다 |
| 파일 단위 Recall | 합격을 예측하지 못함 | "정답 **단락**이 들어왔나"로 재야 한다 |
| 실제 질문의 위키 커버리지 | 21% (AI 초벌 라벨 기준) | 검색을 고치기 전에 문서가 없다 |
| 찾기 점수: 시험지 vs 실제 질문 | 0.77 vs 0.53 | 시험지 점수는 실사용보다 낙관적이다 |
| AI 채점자 일치 | 합격 0.58 → 0.83 · 불합격 0.92 (사람 판정 25건) | 같은 25건으로 다듬은 값이라 과적합 가능성. 목표 85%에 못 미쳐 **"검증 중"** |

- 판정자를 숨기고 재려던 추가 10건은 진행 중에 AI 판정을 본 뒤 사람 표시를 고친 기록이 있어 **산입하지 않았다**. 좋은 숫자가 나왔지만 절차가 흔들린 표본이다.
- 청중이 개발·기획·QA가 섞인 12명이라 본편은 쉬운 말(찾기 / 답하기 / AI 채점자)로 쓰고 깊은 내용은 발표자 교재로 분리했다. 발표 끝에 팀이 "우리 기준"을 정할 수 있게 토론 질문 2개(문서 커버리지 vs 고객 해결, 채점자를 사람과 맞추는 법)를 남겼다.

## 재사용할 원칙
- AI 결과물은 **조건마다 여러 번 돌리고 다수결**로 판정한다.
- 답하기와 찾기를 **분리해서** 잰다. 정답 문서를 직접 준 점수(오라클)가 상한선이다.
- 시험지 점수는 낙관적이다. **실제 질문**으로 한 번 더 잰다.
- 채점하는 AI도 **사람 판정으로 검증**하고, 기준을 못 넘으면 인용하지 않는다.
