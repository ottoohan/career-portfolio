# 오픈 전날, 29개 상품의 가격 계단을 교차 검증하다

**역할**: 시즌 프로모션 판매 설정 검수(혼자) · 이상값 정리 · 오픈 뒤 결과 확인
**기간**: 2026.09 (프로모션 오픈 전날)
**상태**: 이상값 6유형·21건을 오픈 전에 찾았고, 행사가 끝난 뒤 운영 DB로 결과를 확인했다 — 결제에 영향을 주는 두 유형에서 잘못된 결제 0건
**한 줄**: 늦게 살수록 비싸지는 4단계 가격 계단을 29개 상품에 수동으로 설정한 프로모션이었다. 오픈 전날 판매 설정 전체를 뽑아 의도한 계단과 대조해 판매가 2년 동안 이어질 뻔한 종료일 오타를 포함한 이상값을 찾았고, 행사가 끝난 뒤 실제 결제 기록으로 사고가 없었는지 확인했다.

---

## 문제
- 2주짜리 시즌 프로모션. 상품마다 가격이 4단계로 내려간다: 티징(구매 불가, 알림 신청만) → 메인 강의 당일 오전 선착순(최대 할인) → 당일 자정까지 특가 → 기간 종료까지 프로모션가.
- 어드민에 가격 예약 기능이 없어서, 가격이 다른 옵션을 여러 개 만들고 시각별로 노출을 여닫는 방식으로만 구현할 수 있었다. 29개 상품 × 4단계 × 날짜별 = 사람이 손으로 맞춘 설정이 수백 개였다.
- 이런 설정은 틀려도 오류가 나지 않는다. 잘못된 가격이나 기간으로 그대로 팔린다.

## 접근
1. **의도를 먼저 문장으로** — 담당자와 계단 구조(4단계, 전환 시각 11:00·자정, 종료일)를 확인하고 타임라인 그림으로 고정했다.
2. **설정 전체를 뽑아 표로** — 29개 상품의 판매 시작·종료일, 옵션별 가격·노출·수량, 판매 상태를 한 시트로 모았다.
3. **의도와 대조** — 상품마다 "계단이 4단계로 있는가, 시각 경계가 맞는가, 종료일이 행사 종료와 같은가"를 확인했다. 시각 경계(11:00, 자정)를 가장 위험한 지점으로 봤다.

## 찾은 것 (오픈 전날 기준)
| 이상 | 상품 수 | 그대로 열렸다면 |
|---|---|---|
| 판매 종료일 연도 오타(행사 종료 2년 뒤) | 2 | 행사가 끝난 뒤에도 2년 동안 할인가로 판매 |
| 티징 기간인데 이미 구매 가능(판매 시작일이 과거) | 8 | 알림만 받아야 할 기간에 결제 발생, 선착순 공정성 문제 |
| 복제 흔적("(복사)")이 옵션명에 그대로 노출 | 4 | 고객 화면에 내부 작업 흔적 노출 |
| 가격 계단에 구멍(특정 구성에 프로모션가 없음) | 1 | 해당 구성은 할인 없이 판매 |
| 초 단위로 어긋난 종료 시각, 사실상 무제한인 수량 제한 | 3 | 경계 시각 오작동 가능 |
| 행사 대상이 아닐 수 있는 상품 | 3 | 목록 재확인 필요 |

찾은 이상값은 대조 시트로 정리했다. 오픈 전날(9/7·9/8)에는 마케팅 채널에 설정 리스크 점검 계획(옵션 노출 예약 상태·운영 실수 확인)과 날짜별로 어떤 옵션이 보여야 하는지의 기준을 공유하고, 오픈 자정 모니터링을 개발자 2명과 함께 잡았다. 상품별로 누구에게 어떤 수정을 요청했는지의 개별 기록은 남아 있지 않다(처음 이 사례를 쓸 때 "수정 요청 8건"이라고 적었는데, 확인해 보니 8은 요청 건수가 아니라 메모해 둔 이상값 항목 수였다. 정정한다).

## 결과 — 행사 뒤 운영 DB로 확인 (2026.11, 읽기 전용 조회)
| 이상값 | 오픈 뒤 실제 결과 | 판정 |
|---|---|---|
| 종료일 연도 오타 (2종) | 행사 종료 뒤 결제 **0건**, 종료일은 행사 종료 시각으로 바뀌어 있음 | 사고 없음 |
| 티징 기간 구매 가능 (8종) | 29종 전부 티징 기간 결제 **0건**, 첫 결제는 모두 메인 강의 당일 11:00 이후 | 사고 없음 |
| 옵션명 "(복사)" (4종) | 현재 옵션명에 0건 | 현재 정상, 판매 당시 이름은 이력이 없어 미확인 |
| 계단 구멍·초 단위 시각·대상 의심 | 앵콜 판매용으로 설정이 다시 바뀌어 당시 상태를 알 수 없음 | 판정 불가 |

- 결제에 직접 영향을 주는 두 유형(10종)은 실제로 잘못된 결제가 한 건도 없었다.
- 설정 변경 이력이 남지 않는 구조라 **누가 언제 고쳤는지는 알 수 없다.** 내 지적 덕분에 고쳐졌다고 주장하지 않는다. 내 몫은 "찾고, 공유하고, 결과까지 확인한 것"이다.
- 아쉬운 점: 오픈 직전 같은 시트를 한 번 더 돌려 반영 여부를 표에 남겼다면 귀속까지 말할 수 있었다. 다음에는 오픈 직전 재검수를 체크리스트에 넣는다.
- 같은 검수를 다음 시즌에도 돌릴 수 있게 대조 시트(4개 탭)와 타임라인 그림을 남겼다.

## 재사용할 원칙
- **오류가 나지 않는 설정**(가격·기간·노출)은 테스트가 아니라 **의도와의 대조**로 검증한다. 의도를 먼저 문장·그림으로 고정한다.
- 수동 설정이 많을수록 **시각 경계**(오픈 시각, 자정, 종료일)부터 본다.
- 이상값은 "상품 담당자별 수정 요청"으로 묶고, 요청과 반영 여부를 같은 표에 남긴다. 그래야 결과를 내 몫으로 말할 수 있다.
