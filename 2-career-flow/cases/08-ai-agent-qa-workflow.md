# AI 코딩 에이전트로 QA 업무를 재설계하기 — 사용 로그로 개선점을 찾다

**역할**: 개인 업무 환경 설계 · 운영 · 실측
**기간**: 2026
**상태**: 1주 중간 측정 완료(측정 방식 정정 후 재측정), 표본이 작아 본 측정은 12월
**한 줄**: AI 에이전트 세션 한 달치 로그를 집계했다. 교정이 가장 많이 일어나는 지점과 가장 많이 반복하는 일을 찾아 규칙·도구 7가지로 바꿨고, 같은 스크립트로 다시 쟀다.

---

## 문제
- 지침·메모리·훅 같은 기본 셋업은 이미 충분했다. 그런데도 같은 종류의 교정이 반복됐다.
- 한 달치 세션 로그에서 교정 표현을 키워드로 찾으니 40여 건이 나왔다(1차 진단 41건, 고친 스크립트로 40건). 문구를 읽어 보니 **다수가 "기준 오해"**였다. "누적 말고 월별", "메인 말고 베스트", "디자인 말고 HTML" 같은 것들이다.
- 가장 많이 하는 일(운영 문의 원인 파악 84건, 데이터 조회용 즉석 스크립트 400회 이상)에는 전용 도구가 없었다.

## 조치
| 문제 | 바꾼 것 |
|---|---|
| 기준 오해 | **"기준 먼저 출력"** 규칙: 조회·산출 전에 첫 줄에 기간·모수·집계 단위·환경·형식 가정을 적고 바로 진행한다. 묻지 않고 보여 줘서, 틀리면 사람이 그 줄에서 잡게 한다 |
| 반복 조회 스크립트 | **읽기 전용 조회 래퍼**: 키를 출력하지 않고, 쓰기문을 막고, 잡 폴링을 하고, 실행 시각을 표기하고, 최신성을 검사한다 |
| "0건" 오판 | 실시간 복제 DB도 갱신이 멈출 수 있다. **"없음" 판정 전에 활성 테이블의 최근 기록 시각과 현재 시각을 비교**하고, 차이가 크면 "미확인"으로 둔다 (실제로 0건 판정을 한 번 철회했다) |
| 자기 검증 편향 | **독립 검증 에이전트**: 구현자의 설명 없이 diff와 기대 결과 문장만 받아 경계값·회귀·계약 불일치를 반박형으로 찾는다 |
| 원인 파악 반복 | 문의 → 원인 판정(시스템 / 휴먼에러) → 조치 가능 여부를 정해진 형식으로 내는 스킬 |
| 정기 집계 | 주간 휴먼에러 비율을 정해진 정의로 집계해 금요일에 자동으로 보내는 루틴 |
| 긴 세션 | 1세션 1티켓 + 진행 기록 파일 규칙 |

## 결과 — 1주 중간 측정 (같은 스크립트로 다시 돌려도 같은 값)
| 지표 | 개선 전 (10/1~11/3, 150세션) | 개선 후 1주 (11/4~11/11, 56세션) |
|---|---|---|
| 세션당 스킬 호출 | 0.11회 | **0.36회** |
| 교정 비율 | 4.4% | 3.1% |
| 세션당 권한 거부 | 0.11건 | 0.05건 |
| 300분 초과 세션 | 20% | 27% |

- 스킬 사용은 세션당 세 배가 됐다(16회 → 20회, 세션 수는 150 → 56). 그중 11회가 문의 원인 판정 스킬이다 — 절대 건수가 작아 헤드라인으로 쓰지 않는다.
- 교정·거부는 줄어드는 방향이지만 1주 56세션이라 결론으로 쓰지 않는다. 장시간 세션은 늘었다(이 주에 발표 자료 같은 긴 작업이 몰림, 추정) — 다음 개선 대상.
- **측정 방식 정정**: 처음엔 "교정·거부가 늘었다"고 적었다. 공개 후 독립 검토에서 측정 스크립트가 ① 도구 결과 본문의 "rejected" 단어까지 거부로 세고 ② 기간을 파일 수정 시각으로 잘라 재현이 안 되는 문제를 찾았다. 고쳐서 다시 잰 값이 위 표다.
- 독립 검증 에이전트는 11/3~11/12 변경 13건에 실행했다. **차단 1건**(API보다 화면을 먼저 배포하면 운영 화면이 400으로 깨짐 → 배포 순서 고정), 같은 기능의 1차 검증에서 **차단 1건**(중복 복제 판정 반례 → 수정 후 재검증 해소), 확인 필요·주의 20여 건. 테스트를 실행 못 한 경우 "미실행"으로 보고했다.

## 안전장치로 설계한 것
- 운영 DB 쓰기, 강제 푸시, 메인 브랜치 직접 푸시, 실고객 발송 버튼은 **훅으로 차단하거나 규칙으로 금지**했다. 검증은 "실행 직전 확인 화면"까지만 한다.
- 자격증명은 래퍼 안에서만 읽는다. 명령어·로그·산출물에는 남기지 않는다.

## 재사용할 원칙
- AI 활용 개선도 **감이 아니라 로그 실측**에서 시작한다. 가장 많이 하는 일과 가장 많이 고치는 일을 먼저 센다.
- 사람에게 묻는 대신 **가정을 먼저 보여 주는 것**이 왕복을 줄인다.
- 위험한 동작은 지침이 아니라 도구 수준에서 막는다.
- 개선 후에도 같은 스크립트로 다시 잰다. 좋아진 것만 골라 보고하지 않는다.
