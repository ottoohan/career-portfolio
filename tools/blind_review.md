# 블라인드 채점 절차

포트폴리오를 고칠 때마다 같은 기준으로 다시 채점해 점수 변화를 본다. 채점자는 이전 점수나 수정 의도를 모르는 새 AI 에이전트(또는 사람)다.

## 1. 스냅샷 만들기
작업 폴더 대신, 커밋된 상태만 담은 사본을 채점자에게 준다(Notion 매핑 파일은 뺀다).

```bash
cd ~/career-portfolio
R=/tmp/review-$(git rev-parse --short HEAD)
rm -rf "$R" && mkdir -p "$R" && git archive HEAD | tar -x -C "$R" && rm -f "$R/tools/notion_pages.json"
echo "$R"
```

## 2. 채점 프롬프트 (그대로 쓰고, 대상 폴더만 바꾼다)

```text
당신은 IT 회사의 채용 담당 리드(QA·운영 조직)입니다. 아래 포트폴리오를 처음 보고, 지원 직무 "QA + 운영지원(Product Operations)" 채용 관점에서 비판적으로 채점해 주세요. 파일은 읽기만 하고 수정하지 마세요. 지정한 폴더 밖의 파일은 보지 마세요.

- 대상 폴더: `<스냅샷 경로>`
- 읽는 순서: `README.md` → `이력서.md` → `2-career-flow/README.md` → `2-career-flow/경력기술서.md` → `3-why-me/README.md` → `2-career-flow/cases/*.md` 중 관심 가는 것 → 발표 자료 폴더가 있으면 그 README(이미지는 몇 장만). `1-ai-workflow-guide/`, `4-qa-playbook/`은 훑기만.

채점표(100점):
1. 포지셔닝 명확성 — 무엇을 하는 사람이고 왜 이 직무에 맞는지 30초 안에 보이나 (15)
2. 성과의 결과성과 측정 신뢰도 — 활동이 아니라 결과인가, 숫자의 정의·출처·한계가 믿을 만한가 (25)
3. 본인 몫과 팀 몫의 구분, 정직성 (15)
4. 문제 해결의 깊이 — 사례에서 원인 진단·판단 과정이 보이나 (20)

보고(짧게, 한국어):
- 항목별 점수와 한 줄 근거, 총점
- 가장 크게 감점된 약점 3개(파일:줄, 고칠 방향 한 줄)
- 문서끼리 숫자·사실이 어긋나는 곳(파일:줄)
```

## 3. 돌리는 법
- 같은 스냅샷에 **채점자 2명**을 따로 돌려 평균을 낸다. 한 명의 점수는 ±3점 정도 흔들린다.
- Claude Code에서는 새 에이전트 2개를 동시에 띄워 위 프롬프트를 각각 준다. 이전 대화 맥락이 없는 새 세션이어야 한다.
- 두 채점자가 **공통으로 지적한 것**부터 고친다. 한 명만 말한 것은 참고만 한다.
- 고친 뒤에는 `tools/check_numbers.py`와 `tools/check_sanitize.py`를 통과시키고, 커밋한 다음 새 스냅샷으로 다시 채점한다.

### 정체 원인 (r9~r11 공통 지적)
- 숫자를 더 재도 점수가 오르지 않았다. 감점은 "같은 숫자·단서가 5~8곳에 반복", "README·이력서 칸마다 긴 괄호 문장", "정정 이력이 본문 곳곳에 흩어져 방어적으로 읽힘", "발표 AI 4장 vs 직무 초점"에서 나온다.
- 다음 수정은 측정이 아니라 **축약**이다: README는 숫자 3개 + 한 줄, 이력서 불릿은 한 줄씩, 단서는 경력기술서 각주 한 곳, 정정 서사는 사례 02 하나로 모으고, 발표 AI 장은 1~2장으로 줄인다.
- 이미지 캡처는 브라우저 캐시를 피한다(`?v=타임스탬프`로 열고 16장 전체 재캡처, 중복 md5 0 확인).
