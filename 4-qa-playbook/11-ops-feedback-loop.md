# 11. 운영자 의견 조사와 회신

> 내부 도구에도 사용자가 있다. 매달 같은 질문을 하고, **응답마다 처리 결과를 회신**한다. 점수는 보조 지표이고, 결과는 "받은 의견 중 무엇을 처리했나"와 "같은 불편으로 오는 문의가 줄었나"로 본다.

## 고정 문항 (3개, 바꾸지 않는다)

| # | 문항 | 형식 |
|---|---|---|
| 1 | 지금 어드민 만족도는 몇 점인가요? | 0~10 |
| 2 | 어드민으로 일할 때 가장 불편한 점은? (사소한 것도) | 서술 |
| 3 | 가장 시간이 많이 드는 업무·반복 업무는? (어드민 밖도) | 서술 |

문항을 바꾸면 회차끼리 비교할 수 없다. 묻고 싶은 게 생기면 4번 문항을 그 회차에만 붙인다.

## 처리 시트 (응답 시트 오른쪽에 열 추가)

| 열 | 값 |
|---|---|
| 처리 현황 | 완료 / 진행 중 / 이미 있는 기능(안내) / 백로그 |
| 범위 | A 프론트 단독 / B 서버 변경 / C 스키마 변경 — 누가 할 수 있는지가 먼저 정해진다 |
| 코멘트 | 백로그면 사유 한 줄(예: "성능 위험으로 이번에는 보류", "정책 결정 필요") |

## 회신 원칙

- **모든 응답에** 처리 현황을 회신한다. 백로그도 사유를 적어 회신한다.
- "이미 있는 기능"이면 개발 없이 사용법 공지로 닫는다 → [10. 운영 공지](10-ops-notice.md)
- 다음 회차 공지에 "지난달 의견 중 처리한 것"을 먼저 적는다.

## 결과를 보는 법

| 지표 | 쓰는 법 |
|---|---|
| 의견 처리 결과 | 회차별 완료 / 백로그 건수. 이것이 결과 지표다 |
| 같은 불편으로 오는 운영 문의 | 처리한 항목과 같은 유형의 지원 요청이 줄었나 → [09. 운영 문의 판정](09-ops-inquiry-triage.md)의 월 집계로 확인 |
| 만족도 점수 | 보조 지표. 회차마다 응답자가 바뀌고, 응답자가 담당자를 아는 동료라 높게 나오기 쉽다. 추이만 본다 |

## 채운 예시 (한 회차)

| 항목 | 값 |
|---|---|
| 응답 | 20건 |
| 처리 | 완료 12 · 백로그 8 (백로그 모두 사유 회신) |
| 백로그 사유 예 | 게시판 전체 검색은 성능 위험으로 보류 / 옵션별 가격 관리는 다른 기능(얼리버드)으로 대체 가능 |
| 다음 회차 | 지난달 낮게 준 응답자 다수가 점수를 올림, "매달 바뀐다"는 코멘트 |

## 쓰지 않을 때

- 사용자가 5명 미만이면 설문보다 직접 인터뷰가 낫다.
- 처리할 사람이 없으면 조사하지 않는다. 회신 없는 설문은 다음 회차 응답률만 떨어뜨린다.

## 체크리스트

- [ ] 문항 3개를 지난 회차와 똑같이 썼다
- [ ] 모든 응답에 처리 현황과 범위를 적었다
- [ ] 백로그는 사유를 적어 회신했다
- [ ] 결과를 점수가 아니라 처리 건수와 같은 유형 문의 추이로 보고했다
